# Decisions

Cross-cutting decisions referenced by the epics and stories. Statuses: **accepted** / **proposed**
/ **open** / **superseded**. Stories cite them as `D-NN` instead of re-arguing the point. Sibling
decisions are cited with their repository: `firmware D-NN`
(`../sidecartos/docs/epics/DECISIONS.md`), `sidecartos-config D-NN`
(`../sidecartos-config/docs/epics/DECISIONS.md`).

D-04 and D-08 are **as-built**: they record what the working tree already does, read off the code
and confirmed by the sibling sessions on 2026-10-09, so stories can cite them. Correct any that
misstate the intent.

| --- | --- | --- |
| D-01 | **The backlog is committed in this repository**, public as it is. The firmware and the host SWITCHER commit `docs/epics/` because their repositories are private (firmware D-01, sidecartos-config D-01); this repository is public (GitHub, GPL-3.0) and the plan is committed here too, so it travels with the code in the open. Diego, 2026-10-09. | accepted |
| D-02 | **Committed files may name backlog items.** Code comments, `README.md`, `CLAUDE.md` and commit messages may cite `EPIC-NN`, `STORY-NN`, `D-NN` and `C-NN`; a sibling item is cited with its repository (`firmware EPIC-11`, `sidecartos-config EPIC-03`) so the three backlogs never collide. Mirrors the siblings' D-02. Diego, 2026-10-09. | accepted |
| D-03 | **The three repositories are developed in sync.** `sidecartos` (firmware), `sidecartos-config` (host SWITCHER) and this repository form one product. A change to what they share (the protocol version, the flash offsets, the parameters page and catalog layout, the bus commands and replies, the release version and image names; the full list is in `CLAUDE.md`) lands in all three, agreed first with the sibling sessions when they are running (`ListAgents`, `SendMessage`), or reported to Diego with the sibling files that must change when they are not. Diego, 2026-10-09: "the development of these three repos must be in sync in case of changes". Both sibling sessions agreed the same day and record it in their own `CLAUDE.md`. | accepted |
| D-04 | **The rescue ROM talks protocol 0x40 and ships as v4.0.0.** `kSwitcherTosProtocolVersion` is `0x0040` and `src/common/test.c` carries 0x40 at parameters byte 512; `version.txt` is `v4.0.0`. A mismatch shows the incompatibility screen. Matches the firmware's `usbdrive/src/include/constants.h` and sidecartos-config's `helper.h`, checked 2026-10-09. Diego asked for both bumps on 2026-09-09; as-built in the working tree, not committed yet. | accepted |
| D-05 | **Branches as in the siblings.** A version lives on `release/vX.Y.Z`: `release/v4.0.0`, cut from `main` (`a67ea86`) on 2026-10-09 with the v4.0.0 work of the working tree committed on it. Each epic is developed on `epic-NN-<slug>` (the epic folder's name in lower case, e.g. `epic-00-emulator-harness`), cut from the release branch and merged into it by pull request when the epic is done, its verification story included. When the version is done the release branch is merged into `main` and the `v4.0.0` tag is pushed from `main`, which runs `release.yml`. Mirrors firmware D-05 and sidecartos-config D-05. Diego, 2026-10-09. | accepted |
| D-06 | **Hatari and FS-UAE stand in for the machines for everything but the bus.** The emulators boot the image itself as the system ROM: Hatari with `--tos` on an ST or STE, FS-UAE with the 512 KB image as `kickstart_file` on an A500. Only debug+test builds run there: the catalog and parameters page come from `src/common/test.c` and the trace is on (C-03). Every code story runs the harnesses of `tools/dev/` (EPIC-00) before it reaches Diego. The bus command protocol, the real flash, the selection, the reset and power-on timing stay in the hardware-verification stories (C-01). `tools/dev/dev.cfg` and any third-party ROM image are never committed. Mirrors sidecartos-config D-09. Proposed by EPIC-00 and accepted by Diego, 2026-10-09. | accepted |
| D-07 | **Every emulator run uses 512 KB of RAM.** The smallest supported machines are a 520ST and a stock A500, and the ROM's own layout already assumes a RAM top of `0x80000` on both (`src/st/mem.h`, `src/amiga/mem.h`), so the harnesses pin Hatari to `--memsize 0` (512 KB) with no TT-RAM, and FS-UAE to 512 KB of chip RAM with no slow or fast RAM. Mirrors sidecartos-config D-11. Proposed by EPIC-00 and accepted by Diego, 2026-10-09. | accepted |
| D-08 | **One image per computer serves both boards and never depends on the board.** The same three images run against an RP2350A and an RP2350B without a rebuild or a board check: the ROM reads only the parameters page and the catalog through the bus command protocol, which are the same on both boards. The firmware's release images carry the same three files for both boards (firmware EPIC-11, `DEFAULT_ROM/MANIFEST.txt`). Mirrors sidecartos-config D-08. As-built. | accepted |

## Constraints

| ID | Constraint |
| --- | --- |
| C-01 | **A successful build proves nothing about the bus.** There is no test suite. Any protocol, flash, screen or reset change is verified on hardware, with each image it reaches booted on its machine and against every supported board, before its epic closes. |
| C-02 | **One source tree, three images.** `src/common` is platform-agnostic and reaches all three images; `st` and `ste` share `src/st` and differ only by `ROM_BASE_ADDR_UL` and their startup file; `amiga` is `src/amiga`. A change in `src/common` is built and run on all three. |
| C-03 | **No emulator has a SidecarTridge.** Neither Hatari nor FS-UAE answers the bus command protocol: a release image in an emulator times out reading the parameters page and stops at "Error reading the flash page at address 00fff000. Exiting." (seen in Hatari on the ST and STE release images of `0d827d3`, 2026-10-09). Only debug+test builds, with the fake flash of `src/common/test.c`, run in emulators (D-06). A harness PASS says nothing about the bus, the selection, the reset, or hardware timing such as the monitor-detect line at power-on. |
| C-04 | **The firmware is the authority on the parameters page and the flash layout** (`../sidecartos/CLAUDE.md`, firmware C-05). `src/common/chooser.c` mirrors the page by hand: catalog at `0xFF0000`, parameters at `0xFFF000`, default and rescue indices at bytes 70 and 326, the version at 512. A layout change in the firmware is a change here too (D-03). |
| C-05 | **The targets are a 68000 at 8 MHz with 512 KB and nothing but this ROM.** No OS, no libc, no libgcc: a 32-bit `/` or `%` GCC cannot fold fails to link. Interrupts are masked and everything is polled. The RAM layouts in `src/st/mem.h` and `src/amiga/mem.h` and the Amiga's `startup.s` and `rom_abs.ld.S` change together. |
| C-06 | **Every build changes the image hashes, and the firmware pins ours.** `build.sh` fills unused ROM space with random bytes, so no two builds are byte-identical. The firmware's release images (firmware EPIC-11) pin the three `RESCUE_SWITCHER_v4.0.0_*.img` by SHA-256 in `DEFAULT_ROM/MANIFEST.txt`, today from the 2026-09-09 `dist/`, and download them from this repository's GitHub release. Tell the firmware before a rebuild lands in `dist/`; the release pins come from the release assets. |
| C-07 | **After `SELECT_ROM` the firmware does not answer and nothing resets the computer.** It keeps serving the old image for about 55 ms (up to about 410 ms: one 4 KB sector erase, three page programs, a 10 ms watchdog delay), then nothing drives the bus for 26 to 29 ms, then the new image appears. Neither board has a line to the computer's RESET. Reported by the firmware session, 2026-10-09, and checked against `emul/src/tosemul.c` (`write_rom_list()`, `watchdog_reboot()`). |
